# What the published results actually establish

Checked 2026-09-28. Primary papers and author-provided material only. This is a research diagnosis and proposed comparison, not another model-selection result. No raw TEST split was opened, and no measured source or report was changed.

The interaction experiment proposed below has since completed with no meaningful

The papers support several useful mechanisms, but their headline numbers do not establish that our implementation should obtain the same score. None of the papers below supplies a verified, identical ML-100K/all-observed/random-80:10:10/full-catalog/nDCG@10 comparison to the current experiment. Published gains must first be reproduced against the same baseline under the same protocol.

## What is actually missing: three different bottlenecks

| Bottleneck | What it means here | Evidence that would distinguish it |
|---|---|---|
| Algorithm/optimization | Existing inputs might contain useful conditional structure that an additive or poorly optimized model misses. | A stronger predictor improves on identical input information, labels, candidates and selection rules; targeted ablations isolate the useful computation. |
| Objective | Completing every recorded rating models what gets recorded. That is different from predicting whether the viewer will like the movie or be satisfied now. | Declare the real outcome, compare losses against that same outcome, and report the all-observed assignment endpoint separately. Changing the metric is not a model improvement. |
| Information | The log does not show most impressions, availability, deliberate rejections, watch completion, viewing companions or current intent. These can change the right recommendation for the same recorded history. | Acquire a useful signal and compare access versus no access on an identical population, task and budget. More rows of the same biased log do not guarantee resolution. |

These are logically distinct. For an unrecorded user–movie pair, an exposure-and-response model has at least two unknown factors: whether the user encountered the movie and how they would respond. The observed recording event alone does not uniquely identify both. A flexible network can impose useful assumptions, but cannot prove which explanation is true from identical observations. Likewise, two people with the same available history but different unobserved current intentions receive the same deterministic prediction. This is an identifiability argument, not a measured upper bound on MovieLens nDCG; the present evidence does **not** prove we have reached its performance ceiling.

There is primary evidence that useful additional signals address specific failures:

- **Exposure and multiple outcomes:** [KuaiRand](https://arxiv.org/abs/2208.08696) inserts randomly exposed videos into feeds and records 12 feedback types, including click, like and viewing time, alongside histories and features. These observations let researchers distinguish information absent from ordinary positive-only logs. The [official dataset site](https://kuairand.com/) documents the releases. This is evidence of a more informative measurement design, not proof of an automatic accuracy gain or a reason to replace required ML-100K work.
- **Evaluating preference with fewer missing judgments:** [KuaiRec](https://arxiv.org/pdf/2202.10842) contains an almost fully observed 1,411-user × 3,327-item submatrix. Its experiments show that data density and exposure bias can change algorithm rankings in multi-round conversational evaluation. This directly challenges the assumption that a better score on incomplete logs necessarily identifies a better recommender; it does not establish a universal superiority claim for one algorithm.
- **Content when collaborative evidence is absent:** [Deldjoo et al., Movie genome](https://link.springer.com/article/10.1007/s11257-019-09221-y) evaluate audio/visual descriptors and collaborative-informed content representations for genuinely cold movies. Their cold-to-warm analysis also finds that collaborative accuracy becomes strong with very few interactions, while content methods retain coverage/diversity advantages. This supports targeting a particular information gap, not expecting a large warm-user ranking gain merely by appending movie descriptions. Their combined representation/model experiment does not isolate “extra bytes alone” as a causal effect.

The most ambitious useful extension would therefore be a recommender that **chooses what to ask or observe next**, then revises its prediction. For example, one focused preference question may separate two explanations of the same history better than another thousand optimization steps. That is a proposed test, not an established discovery: compare equal query budgets against random questions and a strong passive model, ensure every answer is genuinely withheld until queried, and evaluate on a separate unqueried outcome set. Existing ML-100K ratings can support a clearly labeled simulation, but cannot validate real-time mood, intent or interactive satisfaction. A separately reserved richer dataset or prospective user study would be needed for those claims.

For the assignment, keep ML-100K and the declared all-observed ranking task central. The exact interaction model tests the algorithmic bottleneck now. Richer movie content, explicit elicitation and exposure-aware evaluation are optional supplementary studies with their own declared outcomes, not ways to silently redefine success. We cannot honestly promise a non-incremental gain before measuring it.

## Why a larger number need not mean a stronger model

| Primary source | Verified evaluation setting | Consequence for our comparison |
|---|---|---|
| [EASE, §5.1 and Tables 1–2](https://arxiv.org/pdf/1905.03375) | Table 1 uses ML-20M, Netflix and MSD, user-disjoint evaluation, Recall@20/50 and nDCG@100. Its separate **0.6258 nDCG@10** result is ML-10M: at most 30% of each user's observations train the model, and the remainder form the evaluation truth. | Neither 0.420 at cutoff100 nor 0.6258 on a much larger evaluation-positive set is a target score for our cutoff10 ML-100K task. The second dataset is **ML-10M**, not ML-1M. |
| [Mult-VAE, §4.1–4.3](https://arxiv.org/pdf/1802.05814) | ML-20M and Netflix retain ratings≥4. Users are separated into training/validation/test populations; held-out users provide 80% fold-in history and 20% prediction targets. Hyperparameters are selected using validation nDCG@100. | The user population, relevance definition, cutoff and training information differ from our warm-user, all-record objective. Their main scores are not sampled-negative ML-100K scores. |
| [RecVAE, §4](https://arxiv.org/pdf/1912.11160) | Uses the established ML-20M/Netflix/MSD evaluation family and full ranked outputs excluding known training items. Reports Recall@20/50 and nDCG@100. | Appropriate methodological comparator, not a directly comparable number. |
| [Mamba4Rec, §3.4 and §4.1](https://arxiv.org/html/2403.03900v2) | Timestamp-ordered next-item prediction on ML-1M, Beauty and Video-Games, with users/items below five interactions removed; cutoff10. The paper delegates additional details to RecBole. | Order and next-event prediction differ from our unordered missing-record reconstruction. The inspected paper text does not explicitly establish its candidate-sampling and split details; do not invent them or compare its headline number. |

Candidate sampling is another substantial difference. [Krichene and Rendle, KDD 2020](https://research.google/pubs/on-sampled-metrics-for-item-recommendation/) show that sampled ranking metrics can even reverse algorithm comparisons in expectation. As a mathematical illustration, a sole positive ranked 50th among 1,600 candidates has full-catalog nDCG@10=0. Against 100 uniformly sampled negatives its expected sampled rank is approximately 1+49×100/1599=4.06. The model has not improved. This illustration is not a conversion formula for multi-positive nDCG.

Our dataset has few users, but calling it categorically “sparser than the papers” is misleading. The current study contains 943 user histories; the EASE paper's ML-20M table describes over 136,000 users. Absolute sample count, catalog size, interaction density, positive-set size and rating filtering are different quantities. More training cases may help estimate interactions, but this cross-dataset comparison alone cannot establish the cause of a performance difference. See [the separate local protocol diagnosis](COMPARABILITY.md) for our own old-final versus new-development distinction.

## Mechanisms supported by controlled evidence

**Signed, target-excluding linear relations are already strong.** EASE removes SLIM's nonnegativity constraint and L1 penalty. Its negative-weight-removal ablation reduces ML-20M nDCG@100 from 0.420 to 0.402; SLIM is 0.401. This supports signed conditional corrections in that experiment. These are negative learned relations, not explicit user-dislike labels. Our binary reference already has this mechanism, so repeating it under another name is not a new contribution. [EASE, §5.2](https://arxiv.org/pdf/1905.03375)

**The loss and regularizer matter independently of model depth.** Mult-VAE compares likelihoods with hyperparameters tuned separately. On ML-20M, multinomial/Gaussian/logistic VAE nDCG@100 are 0.426/0.415/0.419. The author-provided [complete ML-20M notebook](https://github.com/dawenl/vae_cf) includes Mult-VAE and Mult-DAE. Their mechanism is a normalized distribution over item events with denoising and controlled latent regularization. This is relevant to our recorded-item objective; it does not claim unobserved items are known dislikes. [Mult-VAE, Table 4](https://arxiv.org/pdf/1802.05814)

**Regularization changes can exceed architecture changes.** The linear-autoencoder analysis derives how dropout regularizes the product of encoder/decoder matrices and scales penalties by feature statistics, unlike separate weight decay. Emphasized denoising excludes identity copying. Its controlled comparisons improve accuracy without adding nonlinear depth. Our exact own-item exclusion already addresses copying, but this work warns against declaring our earlier field architecture intrinsically incapable solely from one optimizer/regularizer. [Steck, NeurIPS 2020, Table 1](https://proceedings.neurips.cc/paper_files/paper/2020/file/e33d974aae13e4d877477d51d8bafdc4-Paper.pdf)

**A credible nonlinear reference needs its training method.** RecVAE combines a previous-encoder composite prior, user-dependent KL weighting and alternating encoder/decoder updates. Its ablation shows that some ingredients worsen results individually but improve them jointly; “more nonlinear layers” is not the demonstrated explanation. The current [author repository](https://github.com/ilya-shenbin/RecVAE) explicitly says its current model differs slightly from the paper and distinguishes RecVAE from RecVAE+ImplicitSLIM. A future reproduction must pin the original implementation or document the changed variant. We should not accidentally present the latter combined model as the requested standalone control. [RecVAE, Table 2](https://arxiv.org/pdf/1912.11160)

**Explicit history conjunctions can correct redundant evidence.** Steck and Liang add pair-of-input-item features with signed coefficients to predict a third item. Their analysis describes downward corrections to an additive model when several similar historical items would otherwise be counted repeatedly; upward corrections can capture complementary evidence. This is the closest prior to our new exact context-interaction kernel, not a novelty-free space. It is not an ensemble: binary and conjunction coefficients are jointly fitted in one predictor. [RecSys 2021 primary author text](https://dawenl.github.io/publications/SteckL21-higher.pdf), [publication DOI](https://doi.org/10.1145/3460231.3474273).

Access limitation: the search service exposes indexed text from that author-hosted higher-order paper, but live opening of the author PDF and publisher page failed during this check. I have therefore not treated secondary copies as primary verification or used their result table for numerical performance claims.

## Selected next mechanism: exact signed context interactions

The immediate custom-model experiment should test a concrete omission in categorical reconstruction: its inputs distinguish rating categories but still contribute additively. The proposed single predictor adds **all distinct pairs of observed source items**, uses a common ridge fit, and excludes every source feature containing the target item. This is an established higher-order idea with a new local implementation, not a claim of inventing interaction modeling. A kernel can avoid materializing the potentially enormous pair-feature matrix.

Our implementation hypothesis is narrow: exact pair features with well-conditioned joint optimization may recover useful context corrections that the earlier bounded, factorized pair operator failed to learn. The earlier operator's failure does not prove all pair interactions useless, and a positive result here would not prove its optimizer was the only cause.

The mathematical identity is straightforward for binary histories: if two users share g source items, they share g(g−1)/2 unordered pairs. A nonnegative pair-feature weight therefore defines a positive-semidefinite polynomial feature kernel. Coefficients can still be signed. For every predicted target, remove its binary feature and **all** pair features involving it; otherwise the conjunctions can copy the target indirectly. The β=0 limit must reproduce EASE exactly.

Before measuring development results:

1. Verify predictions against explicitly enumerated, target-excluded pair features on tiny catalogs; test arbitrary queries, not only unseen-target shortcuts.
2. Use TRAIN-only normalization and freeze the grid, source/data hashes, tie rules and numerical failure rules. Keep a matched expanded binary search and expose the unequal number of tuning opportunities.
3. Fit/select on the same meta cohort, full catalog and all-observed nDCG@10 endpoint; seal all seeds before reading development metrics. Report selected pair strength and whether it falls back to zero.
4. Report multi-positive nDCG together with MRR, Recall, activity groups and head/tail exposure. Inspect whether changes actually reduce repetitive evidence or merely alter popularity; this mechanism interpretation remains a hypothesis unless controlled.
5. Preserve failures and count all fits. The existing development set has been reused and the original TEST has already been seen. A new seal does not provide fresh confirmation; broader claims require another independently reserved evaluation population.

If one additional published standalone neural reference is run later, choose **Mult-VAE with its documented multinomial loss and annealing**, using the author notebook as the reproduction specification. It is a useful objective-and-regularization control beyond our custom field, and less ambiguous to reproduce than selecting an unspecified current RecVAE variant. It is not guaranteed to beat EASE on 943 users. The exact-interaction study is the immediate experiment; the neural reference is a separate proposed comparison, not a completed result.
