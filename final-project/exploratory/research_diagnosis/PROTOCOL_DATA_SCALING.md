# Fixed-query donor-data sensitivity

This is an exploratory diagnosis after the original dataset TEST was evaluated and development was reused. It does not create fresh confirmation. No TEST split, TEST labels, or final-test results will be opened. Prior code, runs, and evidence remain immutable.

The question is whether more **other users' fitting histories** improve binary EASE reconstruction while each queried user's original TRAIN history remains fixed. It does not test new metadata, new item descriptions, longer query histories, future users, or the value of an entirely new dataset.

For each original seed 2026, 2027, 2028, retain the original 471 meta-fit and 472 development users. Sort the meta-fit user IDs, shuffle once with NumPy default_rng(seed + 30011), reserve the first 118 as fixed inner query users, and use the remaining 353 as ordered donors. The donor prefixes are floor(353 × fraction) for fractions 0.25, 0.50, 0.75, 1.00, giving 88, 176, 264, 353 fitting rows. The four fitting sets are nested. Neither inner query nor development users ever have their own row in a fitting set. Every prediction uses that query user's unchanged complete original TRAIN history. All candidate masks use that same history and exclude padding.

Fit the existing independently tested binary reconstruction solver, whose diagonal self-item coefficient is zero, on donor TRAIN rows only. Rating categories are ignored by binary fitting and prediction. For every prefix separately, select lambda from the original declared order 10, 30, 50, 100, 250, 300, 1000, 3000, 10000 by maximum all-observed nDCG@10 on the fixed 118 inner query users. Exact ties retain the earlier lambda. This is 108 candidate fits in total. Selected model serialization and deterministic refit are replayed. Full selected scores are saved locally; no user/item IDs or scores are included in public aggregates.

Persist all twelve chosen configurations, selected-model and score hashes, grids, runtime, source hashes, input hashes, and identity/cohort hashes in one global selection seal **before computing any development metric**. Development evaluation is then read-only: nDCG@10, macro/pooled recall@10/50/100, positive ranks, TRAIN-activity and TRAIN-popularity strata, donor item coverage, and the fraction of positive query items unsupported by donor fitting data. TRAIN activity/popularity definitions use the complete original TRAIN population for consistent comparison across prefixes. Development model choice is forbidden. No confidence interval or significance claim is planned.

Report each seed and equal-seed descriptive means, with all 118 inner and 472 development query counts explicit. Also report donor interaction counts, distinct donor-observed items, query-history fraction with no donor item support, and positive-pair denominators. More donors changes both statistical estimation and item support; this design cannot causally separate them. Item/catalog order and full eligible candidates remain fixed even when a donor prefix has no observations for an item.

The maximum is intentionally 353 other-user donors. Its absolute metrics are not a like-for-like comparison against the earlier 943-row full-system study. Curves do not establish an information-theoretic ceiling or justify extrapolation beyond the observed range. A flat, irregular, or improving curve is to be reported as measured, without adaptive extension or additional lambda search.
